# SCAN — ONE-SHOT BUILD PROMPT (sponsor-track build)

Paste this whole file into Cursor as the task. It is written to be executed in one pass, on the `scan` branch (already checked out, currently identical to `main`).

**Why this version differs from a generic build:** this needs to genuinely win two sponsor prizes, not gesture at them. Gemini API does real work (the actual defect detection + the finding sentence, not a decorative chatbot bolted on), and MongoDB Atlas is the real primary store, not a someday-maybe. Both must survive being asked "show me the actual API call" by a judge.

---

## GOAL

Build a mobile-web app that scans walls and surfaces with a phone camera, detects mold / water seepage / cracks / peeling paint, stores each scan as a measurement, and **shows how a surface has changed between scans over time.**

The live camera view must feel instant with zero API keys (a fast local mock drives the on-screen bounding-box preview while aiming). The moment the user presses the shutter, the frozen frame goes to the server and — when `GEMINI_API_KEY` is set — **a real Gemini multimodal call produces the actual stored detections and the finding sentence.** No key → clean fallback to the mock, clearly labeled as mock in the UI so nobody accidentally demos fake data as real.

Working name: `SCAN`. Rename later; do not invent branding.

## STACK — do not substitute

- Next.js App Router + TypeScript (already in the repo)
- Tailwind if already configured; otherwise plain CSS modules. Do not add a UI library.
- **MongoDB Atlas via the official `mongodb` driver — this is the real primary store.** `MONGODB_URI` is already set in `.env.local` and in Vercel's project env vars (reused from the previous app on the same Atlas cluster) — **point at a distinct database name, `client.db("scan")`, so collections never collide with the old app's `users`/`quests`/`transactions`.** Still implement the in-memory fallback for when `MONGODB_URI` is absent (good practice, costs nothing, keeps `npm run dev` working with zero config on a machine that hasn't pulled `.env.local`) — but on this machine, with the URI present, it should be running on real Mongo from the first request.
- **Gemini API via `@google/genai` (the current official Google Gen AI SDK — `npm install @google/genai`) — this is the real detector.** Requires `GEMINI_API_KEY` (get a free key at ai.google.dev/Google AI Studio — not yet in `.env.local`, someone needs to add it). Use a current fast multimodal model (`gemini-2.5-flash` as of this writing — check https://ai.google.dev/gemini-api/docs/models if that's been superseded by the time you're reading this) with `responseMimeType: "application/json"` and a response schema so the output is structured, not prose to parse by hand.
- Image storage: `@vercel/blob` when `BLOB_READ_WRITE_TOKEN` is set; otherwise store the image as a data URL in the record. The app must work with neither.
- No auth, no login, no accounts.

## TYPES — `src/lib/types.ts` — implement exactly

```ts
export type DefectClass = "mold" | "water_seepage" | "crack" | "peeling_paint";

export type Detection = {
  cls: DefectClass;
  confidence: number;              // 0..1
  bbox: [number, number, number, number]; // x, y, w, h — NORMALISED 0..1
  areaRatio: number;               // share of frame, 0..1
};

export type Property = {
  id: string;
  label: string;                   // "5614 Beacon St"
  kind: "lease" | "sublet" | "stay";
  createdAt: string;               // ISO
};

export type Scan = {
  id: string;
  propertyId: string;
  room: string;                    // "bathroom"
  surface: string;                 // "ceiling_vent"
  imageUrl: string;
  capturedAt: string;              // ISO
  detections: Detection[];
  totalAffectedRatio: number;      // sum of areaRatio, clamped 0..1
  finding: string;                 // one sentence
  detector: "gemini" | "mock";     // which one actually produced this — shown in the UI, never hidden
  review?: Review;
};

export type Review = {
  verdict: "confirmed" | "disputed";
  reviewerRole: "tenant" | "owner" | "inspector";
  note?: string;
  at: string;
};

export type SurfaceCoverage = {
  room: string;
  surface: string;
  lastScannedAt: string | null;
  scanCount: number;
};
```

**`totalAffectedRatio` is the time series.** Everything in the report trends off it. **`detector` is the sponsor-track receipt** — a judge should be able to see, per scan, whether Gemini actually ran.

## THE DETECTOR — `src/lib/detect.ts` — the sponsor-track seam

```ts
export interface Detector {
  name: "gemini" | "mock";
  detect(imageDataUrl: string): Promise<{ detections: Detection[]; finding: string }>;
}
```

Note this returns **both** detections and the finding sentence from one call — Gemini can produce both in a single structured response, which is fewer API calls and a cleaner story than two separate LLM calls for "detect" and "then describe."

**`GeminiDetector` (the real one, selected automatically when `GEMINI_API_KEY` is set):**
- Send the captured frame (base64 data URL, stripped of the `data:image/...;base64,` prefix, passed as inline image data) to Gemini with a prompt instructing it to look for mold, water seepage, cracks, and peeling paint, and return **strictly** the schema below — no markdown fences, no prose outside the JSON.
- Use `responseMimeType: "application/json"` with a `responseSchema` matching:
  ```json
  {
    "detections": [
      { "cls": "mold|water_seepage|crack|peeling_paint", "confidence": 0-1, "bbox": [x,y,w,h] (normalized 0-1), "areaRatio": 0-1 }
    ],
    "finding": "one plain-English sentence describing what's visible and how concerning it is"
  }
  ```
- If Gemini returns 0 detections on a clean surface, that's a valid, real result — `finding` should say something like "No visible mold, seepage, cracking, or peeling detected." Do not force a minimum count.
- Wrap the whole call in a try/catch: on any error (network, parse failure, rate limit, malformed schema), fall back to `MockDetector` for that single request and log the error server-side — **never let a Gemini hiccup break the shutter flow.**
- Clamp/validate every returned number into its documented range before trusting it (LLMs occasionally return `1.2` for a 0-1 field) — don't let bad data corrupt `totalAffectedRatio`.

**`MockDetector` (fallback, and also what `livePreview.ts` mirrors client-side for the live overlay):**
- Returns 0–3 plausible detections, deterministic from a hash of frame dimensions + a time bucket so boxes are stable for ~1s rather than strobing.
- Biases `mold` and `water_seepage` higher than `crack`.
- Confidences in 0.45–0.92.
- Boxes inside 0.05–0.95 normalised bounds.
- `finding`: a template sentence built from the detections, e.g. `"Preview only — looks like possible {cls} near center-left."`

Selection: `DETECTOR` env var (`gemini` when `GEMINI_API_KEY` present, else `mock`), with an explicit override still possible by setting `DETECTOR=mock` even with a key present (useful for testing the fallback path on purpose).

**Nothing outside `lib/detect.ts` may know which detector produced a result** — except reading the `detector` field already stored on the `Scan` for display purposes (that's data, not detector-selection logic).

**Live preview is separate and does not go through this file at all.** `src/lib/livePreview.ts` is a tiny client-only module used only by `Viewfinder.tsx` for the continuous on-screen boxes while aiming — same deterministic-mock math as above, but it never calls `/api/detect` and never runs on every frame's actual measurement. This exists purely so aiming the camera feels alive without hammering Gemini (or even the network) 10+ times a second. Only the frozen shutter frame goes to the real server-side detector.

## NEXT-BEST-CAPTURE — `src/lib/nextbest.ts`

```ts
export function nextBestSurface(
  covered: SurfaceCoverage[]
): { room: string; surface: string; reason: string };
```

Score every known surface:

```
value = priorRisk(surface) * (1 - coverage) * recencyDecay(lastScannedAt)
coverage      = min(scanCount / 2, 1)
recencyDecay  = 1 for never scanned; else min(hoursSince / 168, 1)
```

Hard-code the priors (these are the domain knowledge and the whole Optimization claim):

```ts
bathroom_ceiling 0.95 · under_sink 0.90 · window_frame 0.85
exterior_wall 0.75 · behind_furniture 0.70 · around_vent 0.70
basement_wall 0.85 · closet_corner 0.60 · kitchen_backsplash 0.55
ceiling_general 0.50 · wall_general 0.35
```

`reason` must be human-readable: `"never scanned · high-risk surface"`.

## PROGRESSION — `src/lib/progression.ts`

```ts
export function surfaceTrend(scans: Scan[]): {
  points: { at: string; ratio: number }[];   // sorted ascending
  first: Scan | null;
  latest: Scan | null;
  deltaRatio: number;        // latest - first
  percentChange: number | null; // null when first ratio is 0
  direction: "worsening" | "improving" | "stable" | "insufficient_data";
};
```

`stable` when |deltaRatio| < 0.01. `insufficient_data` with fewer than 2 scans.

## API ROUTES — exact contracts

```
POST /api/properties   { label, kind }                        -> { property }
GET  /api/properties                                          -> { properties }

POST /api/scans        { propertyId, room, surface, image }
                       // image: data URL. Server calls the real detector here — client sends
                       // ONLY the frame, never fabricated detections. This is the point where
                       // Gemini actually runs.
                       -> { scan }   // server computes detections, totalAffectedRatio, finding, detector
GET  /api/scans?propertyId=&room=&surface=                    -> { scans }
GET  /api/scans/:id                                           -> { scan }
POST /api/scans/:id/review  { verdict, reviewerRole, note }   -> { scan }

POST /api/detect       { image }                              -> { detections, finding, detector }
                       // exposed separately too, in case the client wants to preview before
                       // committing to a scan — same underlying call as /api/scans
```

Server computes `totalAffectedRatio`, `finding`, and `detector` — **never trust the client for any of those three.** This is also the anti-gaming answer if a judge asks "couldn't I fake a detection" — same shape as Quest's "only the requester can confirm" rule: the client can request a scan, only the server can decide what it found.

## SCREENS

**1. `/` — Home**
List properties with last-scanned time and worst current `totalAffectedRatio`. Create-property form (label + kind). Big primary button to `/scan`.

**2. `/scan` — the important one**
- Live camera, rear-facing, filling the viewport.
- Canvas overlay drawing the **live preview** boxes (from `livePreview.ts`, not Gemini) with class-coloured boxes and `cls + confidence%` labels — plus a small "preview" chip (`DetectorBadge`) so it's visually distinct from a committed result.
- `SurfacePrompt` at the top: *"Point at the bathroom ceiling — never scanned, high-risk surface."*
- Room + surface selectors (prefilled from `nextBestSurface`).
- Big shutter button: freeze the frame, show a brief "analyzing" state, POST to `/api/scans`, then show the real result — the `DetectorBadge` now says "Gemini" (or "Mock" if no key), the finding sentence, and the detections drawn with `BoxOverlay` on the frozen frame. Then return to live.
- Detection loop for the *live preview only*: downscale the frame to max 416px, call `livePreview` (synchronous, no network), `requestAnimationFrame` to draw. The real Gemini call happens exactly once, on shutter press, against the full-resolution frozen frame.

**3. `/report/[propertyId]`**
- Grouped by room → surface.
- Each surface shows `Timeline` of `affectedRatio`, and `CompareView` of first vs latest image side by side with both numbers and the delta.
- Direction badge: worsening / improving / stable.
- Each scan shows its `DetectorBadge` (Gemini/Mock) — a report full of real Gemini calls is the sponsor-track evidence.
- Review buttons: Confirm / Dispute, with the role picker. Unreviewed findings are labelled **"Unreviewed — not a claim."**

## CAMERA REQUIREMENTS — these will otherwise cost an hour each

- `navigator.mediaDevices.getUserMedia({ video: { facingMode: { ideal: "environment" } }, audio: false })`
- The `<video>` element **must** have `playsInline`, `muted`, `autoPlay`. Without `playsInline` iOS Safari goes fullscreen and the overlay vanishes.
- Camera start must be behind a user gesture (a "Start camera" button) — iOS blocks autostart.
- Canvas overlay absolutely positioned over the video, matching its *rendered* size; recompute on resize and orientation change.
- Boxes are normalised 0..1 — multiply by rendered canvas dimensions at draw time, never by intrinsic video dimensions.
- Show a clear permission-denied state with a retry button. Never leave a black rectangle.
- **Do not use LiDAR / ARKit depth APIs.** Not accessible from mobile web at all (native-only), only exists on Pro iPhones, and this is a 2D visual classification problem, not a depth problem — it would break the "join in 10 seconds from a QR code on any phone" requirement for zero benefit.
